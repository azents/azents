# Operation-Scoped Execution and Lifecycle Requirements

## Primary System Outcome

Execution and lifecycle work retains exact winning claims, one-time capability consumption and obsolete critical result rejection without imposing blanket root/Agent/ancestor locking on ordinary descriptions, harmless private state or cleanup enumeration.

## Confirmed Scope

This is the final execution/lifecycle and residual-audit phase of the requester-confirmed defensive-lock removal sequence. The requester directed continued implementation and latest-SHA CI verification after the broad session-capability foundation. Existing public execution, resource, privacy and security outcomes remain authoritative. This snapshot does not create a new API, owner token, policy or recovery mode.

## Requirements

### REQ-1 — No inherited descriptive gate

Ordinary model preparation, event/result/status projection, private descriptive state, tree/Project view and cleanup enumeration do not acquire a generic root-tree ownership gate. Description may lag or become unavailable; it never authorizes a real side effect.

### REQ-2 — Claims and consumption remain single-winner

Session owner acquisition, pending Run activation, scheduled/ingress work and destructive job/resource claims preserve one accepted winner under competing Workers and lease reclaim. Existing one-time ticket/OAuth/enrollment consumption remains exact. Ordinary readers do not inherit claim/consumption exclusion.

### REQ-3 — Critical owned results commit atomically

Obsolete execution cannot persist current model/tool outputs, usage/turn markers, active call state, mailbox promotion, terminal disposition or parent result delivery. Each dependent multi-row group remains atomic and conditioned on exact Session/Run/call/owner/attempt identity. Parent terminal delivery remains one disposition plus one idempotent mailbox admission, not independent best-effort writes.

### REQ-4 — Stop, hierarchy and irreversible lifecycle outcomes remain

Concurrent child creation, Stop/archive/decommission/purge and restore keep existing reachability and security outcomes. A child cannot escape an admitted critical subtree transition through a descriptive enumeration race. After the irreversible fence, restore cannot win. Existing tombstone/participant and pending/running settlement contracts remain.

### REQ-5 — Resource and publication identity remains exact

Runtime reports/recreation/removal and path cleanup act only on the exact generation, lease/attempt, target/configuration and acknowledged resource. Replaced resource or obsolete producer results cannot become current. Ordinary Runtime/path status reads do not inherit destructive-operation coordination. Parent/child path overlap cannot be reduced to exact-path uniqueness without preserving existing removal safety.

### REQ-6 — Close the entire residual inventory

Remove all non-exempt explicit row/advisory locks and indirect generic wrapper gates in the affected system. Every remaining operation is attributed to one winning claim, one-time consumption or critical obsolete-result/security mutation with exact scope and deterministic proof. Source occurrence counts are not runtime frequency or unnecessary-lock percentages.

## Constraints and Non-Goals

- Preserve existing APIs, tenant/actor checks, owner/generation/lease/status fields, resource identity and normal conflict outcomes.
- No schema, new token/version authority, cache, compatibility fallback, discovery/static-prompt policy or rollout mode.
- Ordinary database writes/constraints/transaction atomicity remain; an early application comparison is not a critical commit fence.
- No Agent merge, deployment, live infrastructure mutation or alert dismissal.

## Acceptance

Deterministic real database claim/handover/stale-result/Stop/purge/parent-delivery/resource tests, full backend quality/tests, relevant required E2E and delivered-SHA CI pass. Successful description paths remain nonblocking under held writer/owner rows. Final row/advisory/raw SQL/indirect wrapper caller audit has no non-exempt or unclassified operation.
