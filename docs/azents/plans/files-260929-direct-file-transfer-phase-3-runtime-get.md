- Integration order: `Inspect current source authorities and late-digest staging → represent verified direct source and cleanup durably → wire coordinator/claim presigner → switch managed consumers → switch external ingress → root-integrated verification/review → commit/stacked PR.`
- Phase 3 source distinction: existing Workspace Upload keeps an external immutable `source_handle` with its hash fixed at admission; these feature consumers use the admitted attempt-owned transfer object as their direct GET source. A provider's authenticated declared size is admitted before its body is opened, and its real digest is bound with that verified object at READY. Existing object cleanup evidence transfers atomically at READY. No direct GET claim uses an unverified or nullable digest, and no direct attempt is eligible for the legacy DownloadTransfer byte stream.
- Authority boundary: adapters revalidate their existing feature access immediately before READY/dispatch. The immutable, verified attempt-owned object is the Runner GET source. Claim rechecks the exact current attempt, authenticated Runner generation, deadline, source expiry, cancellation and trusted object manifest. It does not introduce an original-file revocation mechanism or re-fetch the original provider at claim. This follows existing File Exchange Storage/Runtime Control Specs and ADR-D2's dispatch boundary; the requester clarified that the proposed additional source-authority service is unsupported scope.
