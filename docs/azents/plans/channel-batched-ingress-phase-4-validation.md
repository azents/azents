- Phase: `4 — Validation, Specs, and cleanup`

- PR boundary: Add M12 active-ingress diagnostics and bounded metrics, complete deterministic validation of M1–M12, promote current Living Specs, mark the approved snapshot implemented, and remove all temporary feature plans.
- Inputs: Phase 1 common Job Runtime and packaging, Phase 2 canonical mailbox and migration, Phase 3 durable admission/queue/drain/cursor/recovery implementation, approved Design revision 1, and fresh PostgreSQL/testenv prerequisites.
