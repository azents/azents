- Picker contract: Available only for an authorized saved connected Google target with Drive enabled, actual `drive.file`, usable server refresh credential and optional prepared browser fields. Request precisely `drive.file` through the supported OAuth SDK; require positive exact returned scope evidence, bearer type and usable expiry. Never deliver a broader/unknown token or the main stored token. Never overwrite the main access token/granted scopes with a scoped receipt. Unexpected refresh rotation is preserved only under exact-current identity/credential fencing and sets existing reconnect-required status while returning no browser token. Newer grants remain untouched. The browser keeps the transient credential in memory only, clears it on close/unmount/expiry, and treats selected IDs as untrusted interaction results rather than local authorization.
- UI flow: Reuse current setup/review/callback and saved settings. Managers select services and understandable Google request bundles before consent, inspect actual granted capabilities, then publish. Saved service toggles save locally; scope intent changes use ordinary reconnect. Default new Drive access to whole-Drive request selection without modifying old grants. Mixed readonly/app-file grants remain whole-read/app-file-write, and all-off remains connected/inactive. Picker is an optional saved-management action with explicit selection/cancellation feedback, not an in-conversation approval. Retain existing layout/components and account-used-by-shared-Agent guidance; add consequence copy only where non-obvious.
