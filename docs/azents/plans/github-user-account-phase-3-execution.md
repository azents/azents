## Execution and Safety Contract

- Runtime authority derives from the resolved Team Session's existing canonical context and Toolkit delegation, not the OAuth manager's session, sender, viewer or another GitHub account. Current Toolkit presence, enabled/attachment/ownership, Workspace/AgentSession identity and registration/App source remain fail-closed.
- Resolve active token facts immediately before supported discovery/call/process dispatch. Do not expose an encrypted staged candidate or retired token, or reuse installation/PAT TTL cache as user authority. A disconnected or replaced current row cannot silently fall back.
- MCP calls use the already available `headers_provider` affordance for both live and snapshot-backed wrappers. Definitive authentication failure affects only its captured connection ID; target/SSO/403/404 and transient provider transport failure do not clear unrelated access. No mutating action retry after an uncertain result.
- Opt-in Runtime exposure remains off by default and uses GH_TOKEN/GITHUB_TOKEN only, with existing merge precedence and raw-process credential disclosure. `_collect_secret_env` immediately before `start_process` is the inspected boundary. Do not claim already running commands, older terminal environments, admitted requests or token copies are recalled.
- Provider HTTP, MCP and Runtime effects remain outside database transactions. Exact local token cleanup remains bounded fail-open from phase 1; no lifecycle extension or proof protocol.
- Synthetic fixture identities/settings must be explicit and no provider body/code/token/key is copied into evidence. Required CI is credential-free. Optional live GitHub prerequisites remain unauthorized/unrun and are reported separately, not counted as success.
