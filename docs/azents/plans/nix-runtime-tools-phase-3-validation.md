## Context Checkpoint

- Status: The disposable Kind/Calico/local-registry substrate, production Provider v3 lifecycle driver, required product E2E, Docker parity script, and combined CI gate are implemented and independently reviewed. Focused deterministic validation is green; the complete disposable-cluster journey remains CI-authoritative because the local Agent Runtime recycles its Docker substrate during long image-build/cluster sessions before the full journey can finish.
- Validation discovery and correction: native Nix 2.35 creates the default `nix profile` root at `${NIX_STATE_HOME}/profiles/profile`. The Phase 2 Runner PATH incorrectly pointed to `${NIX_STATE_HOME}/nix/profiles/profile/bin`, so `nix profile add nixpkgs#hello` succeeded while `hello` remained unavailable. The Runner environment, image PATH, profile script, and tests now use `/nix/var/state/azents-agent/profiles/profile`; no product authority or lifecycle boundary changed.
- Docker parity evidence: the current worktree Runner image initialized an empty bind-backed store, installed and executed `hello`, preserved it through network-disabled container replacement, preserved offline catalog search, removed the Nix state through the explicit reset boundary, and restarted without `hello` while retaining offline search. The script cleans immutable store content through a root container.
- Kubernetes partial local evidence: a run-unique Kind `v0.32.0` cluster with pinned Kubernetes `v1.36.1`, dedicated temporary kubeconfig, Calico `v3.30.3`, dynamic `standard` StorageClass, and loopback-only dynamic registry started successfully without ambient-cluster access. Earlier evidence reached Provider-created distinct Workspace and Nix PVCs, Runner bootstrap, `hello` install/execution, and ordinary Pod recreation persistence.
